AGENTS.md Template

41|

El archivo de instrucciones principal. Máximo ~80 líneas. Routing layer que apunta a docs/ detallados.

42| 
# AGENTS.md — [Project Name]
    43|
    44|[One-sentence project purpose]
    45|
    46|## Startup Workflow
    47|Before writing code:
    48|1. Read this file
    49|2. Read docs/ARCHITECTURE.md
    50|3. Run ./init.sh
    51|4. Read feature_list.json (current state)
    52|
    53|## Working Rules
    54|- One feature at a time — no scope creep
    55|- Verification required before claiming done
    56|- Update progress before ending session
    57|- If unsure, check docs/ or ask
    58|
    59|## Required Artifacts
    60|- `feature_list.json`: Feature state tracker
    61|- `progress.md`: Session continuity log
    62|- `init.sh`: Standard startup and verification
    63|
    64|## Definition of Done
    65|A feature is done when:
    66|- [ ] Implementation complete
    67|- [ ] Verification passed (tests, type checks)
    68|- [ ] Evidence recorded in feature_list.json
    69|- [ ] Repository restartable from clean state
    70|
    71|## End of Session
    72|Before ending:
    73|1. Update progress.md
    74|2. Update feature_list.json
    75|3. Record blockers/risks
    76|4. Commit with descriptive message
    77|5. Leave clean restart path

feature_list.json Template

82|

Single source of truth para el progreso del proyecto. Cada feature con id, dependencias, estado, y evidencia.

83| 
{
    84|  "features": [
    85|    {
    86|      "id": "feat-001",
    87|      "name": "Feature Name",
    88|      "description": "Description of the feature",
    89|      "dependencies": [],
    90|      "status": "todo",
    91|      "evidence": ""
    92|    },
    93|    {
    94|      "id": "feat-002",
    95|      "name": "Another Feature",
    96|      "description": "Description",
    97|      "dependencies": ["feat-001"],
    98|      "status": "in-progress",
    99|      "evidence": ""
   100|    }
   101|  ]
   102|}
   103|
   104|/* Status lifecycle:
   105|   todo → in-progress → review → done
   106|   A feature is "done" only when evidence field is populated
   107|*/

init.sh Template

112|

Script de inicialización que se ejecuta al inicio de cada sesión. Verifica que todo esté listo para trabajar.

113| 
#!/bin/bash
   114|set -e
   115|
   116|echo "=== [init.sh] Starting initialization ==="
   117|START_TS=$(date +%s)
   118|
   119|echo "=== Installing dependencies ==="
   120|npm install  # or: cargo build, pip install -r requirements.txt, etc.
   121|
   122|echo "=== Running type checks ==="
   123|npm run check  # or: cargo check, mypy, tsc --noEmit, etc.
   124|
   125|echo "=== Running tests ==="
   126|npm test  # or: cargo test, pytest, etc.
   127|
   128|echo "=== Building application ==="
   129|npm run build  # or: cargo build --release, etc.
   130|
   131|echo "=== Checking feature list ==="
   132|if [ -f feature_list.json ]; then
   133|    STATUS_COUNT=$(grep -c '"status"' feature_list.json || true)
   134|    echo "  Feature list loaded: entries found"
   135|else
   136|    echo "  WARNING: feature_list.json not found"
   137|fi
   138|
   139|DURATION=$(( $(date +%s) - START_TS ))
   140|echo "=== [init.sh] Complete (${DURATION}s) ==="

progress.md Template

145|

Log de progreso de sesión. Se actualiza al final de cada sesión para mantener continuidad.

146| 
# Session Progress Log
   147|
   148|## Current State (Last Updated: YYYY-MM-DD HH:MM)
   149|
   150|**Active Feature:** feat-001 - Feature Name
   151|**Status:** In Progress (XX% complete)
   152|
   153|### What's Done
   154|- [x] Task completed this session
   155|- [x] Another completed task
   156|
   157|### What's In Progress
   158|- Current task being worked on
   159|- Decision needed: option A vs option B
   160|
   161|### Blockers
   162|- Blocker description (waiting on decision, external dependency, etc.)
   163|
   164|### Next Session Should
   165|1. First task for next session
   166|2. Second task for next session
   167|3. Third task for next session

Session Handoff Template

172|

Template para transferir contexto entre sesiones del agente.

173| 
# Session Handoff
   174|
   175|## Session ID: [date-uuid]
   176|## Completed: YYYY-MM-DD HH:MM
   177|
   178|## What Was Accomplished
   179|- [Brief summary of what was done]
   180|
   181|## Key Decisions
   182|- Decision 1: [what was decided and why]
   183|- Decision 2: [what was decided and why]
   184|
   185|## Files Modified
   186|- path/to/file.rs — [what changed]
   187|- path/to/file2.rs — [what changed]
   188|
   189|## Files Created
   190|- path/to/new-file.rs — [purpose]
   191|
   192|## Current State
   193|- feature_list.json status: [summary]
   194|- Branch: [branch-name]
   195|- Uncommitted changes: [yes/no]
   196|
   197|## Known Issues
   198|- Issue 1: [description]
   199|- Issue 2: [description]
   200|
   201|## Next Steps
   202|1. [Next action item]
   203|2. [Next action item]
   204|
   205|## Notes
   206|- [Any additional context for the next session]

Harness Assessment Checklist

211|

Evalúa tu harness actual en los 5 subsistemas. Puntúa 1-5 cada uno.

212| 213|

1. Instructions (Recipe Shelf)

214|
    215|
  • ¿Existe un AGENTS.md / CLAUDE.md?
    • 216|
  • ¿Tiene progressive disclosure (corto, enlaza a docs/)?
    • 217|
  • ¿Define startup workflow claro?
    • 218|
  • ¿Especifica qué leer antes de codificar?
    • 219|
  • ¿Las reglas son ejecutables, no abstractas?
    • 220|
221| 222|

2. State (Prep Station)

223|
    224|
  • ¿Existe un feature_list.json o equivalente?
    • 225|
  • ¿Cada feature tiene id, dependencias, estado, y evidencia?
    • 226|
  • ¿Hay session handoff template?
    • 227|
  • ¿Se actualiza el progreso al final de cada sesión?
    • 228|
229| 230|

3. Verification (Quality Check)

231|
    232|
  • ¿init.sh corre verificación automática?
    • 233|
  • ¿Hay tests que validen el trabajo del agente?
    • 234|
  • ¿Hay type checks en el pipeline?
    • 235|
  • ¿El agente no puede declarar "done" sin verificar?
    • 236|
237| 238|

4. Scope (Task Boundaries)

239|
    240|
  • ¿Hay política de una feature a la vez?
    • 241|
  • ¿Están documentadas las dependencias entre features?
    • 242|
  • ¿Hay Definition of Done checklist?
    • 243|
  • ¿Hay next-task templates para evitar overreach?
    • 244|
245| 246|

5. Lifecycle (Session Management)

247|
    248|
  • ¿Existe init.sh?
    • 249|
  • ¿Hay clean-state checklist?
    • 250|
  • ¿Hay procedimiento de handoff documentado?
    • 251|
  • ¿Los benchmarks miden mejora del harness?
    • 252|
253| 254|

Puntúa 1-5 cada subsistema. El de menor puntuación es tu bottleneck. Mejora allí primero.
